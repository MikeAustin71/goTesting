## AGM core iteration in Macrobot form

Here’s the “true” AGM iteration, expressed as a Macrobot‑level helper that only knows how to take an initial pair $(a_0,b_0)$ and drive them to their common limit.

#### Macrobot signature

```go
// naturalLogAGMMacrobot.go

package naturalLogCalcs

import (
	"math/big"

	ePref "github.com/MikeAustin71/errpref"
)

type naturalLogAGMMacrobot struct{}
// agmCore
//
// Computes the arithmetic–geometric mean of (a0, b0) using the
// classical iteration:
//
//   a_{n+1} = (a_n + b_n) / 2
//   b_{n+1} = sqrt(a_n * b_n)
//
// Preconditions:
//   - a0, b0 non‑nil
//   - a0, b0 > 0
//   - precBits > 0
//
// On success, returns AGM(a0, b0) as *big.Float with precision precBits.
func (agmMacro *naturalLogAGMMacrobot) agmCore(
	a0, b0 *big.Float,
	precBits uint,
	errPrefDto *ePref.ErrPrefixDto,
) (*big.Float, error) {

	ePrefix, err := ePref.ErrPrefixDto{}.NewFromErrPrefDto(
		errPrefDto,
		"naturalLogAGMMacrobot.agmCore()",
		"",
	)
	if err != nil {
		return new(big.Float), err
	}

	if a0 == nil {
		return nil, &InputPtrNilError{
			ErrPrefix:     ePrefix.String(),
			ErrContext:    "",
			ParameterName: "'a0'",
		}
	}
	if b0 == nil {
		return nil, &InputPtrNilError{
			ErrPrefix:     ePrefix.String(),
			ErrContext:    "",
			ParameterName: "'b0'",
		}
	}

	// Both arguments must be strictly positive for the classical AGM.
	if a0.Sign() <= 0 || b0.Sign() <= 0 {
		return nil, &FuncReturnError{
			ErrPrefix:  ePrefix.String(),
			ReturnFunc: "agmCore(a0, b0, precBits)",
			ErrContext: "Inputs must be strictly positive.",
			ErrMessage: "non‑positive AGM arguments are not supported",
		}
	}

	// Working precision: small safety margin above requested precision.
	workingPrec := precBits + 16

	newF := func() *big.Float {
		return new(big.Float).
			SetMode(big.AwayFromZero).
			SetPrec(workingPrec)
	}

	a := newF().Set(a0)
	b := newF().Set(b0)

	// Helper for sqrt with our existing BigFloatMath.
	sqrtCalc := new(BigFloatMath)

	// Tolerance: 1 ulp at requested precision.
	// We’ll detect convergence via equality at workingPrec,
	// which is effectively stricter than 1 ulp at precBits.
	maxIter := uint64(precBits*4 + 64) // generous upper bound

	tmpSum := newF()
	tmpProd := newF()

	for i := uint64(0); i < maxIter; i++ {

		// aNext = (a + b) / 2
		tmpSum.Add(a, b)
		aNext := newF().Quo(tmpSum, newF().SetFloat64(2.0))

		// bNext = sqrt(a * b)
		tmpProd.Mul(a, b)

		bNext, err := sqrtCalc.SqrtBigFloat(
			tmpProd,
			0,          // let sqrt compute integerDigits
			workingPrec,
		)
		if err != nil {
			return nil, &FuncReturnError{
				ErrPrefix:  ePrefix.String(),
				ReturnFunc: "SqrtBigFloat(a*b, workingPrec)",
				ErrContext: "",
				ErrMessage: err.Error(),
			}
		}

		// Convergence: at this working precision, equality is a strong test.
		if aNext.Cmp(bNext) == 0 {
			a = aNext
			b = bNext
			break
		}

		a = aNext
		b = bNext
	}

	// Round to requested precision.
	out := new(big.Float).
		SetMode(big.AwayFromZero).
		SetPrec(precBits)

	out.Set(a) // a and b are equal to requested precision

	return out, nil
}
```

## Nanobot/Molecule/Atom wiring around `agmCore`

At the Nanobot level we typically hide the raw $(a_0,b_0)$ construction and precision plumbing, and present a “kernel” that the Molecule/Atom layers can call.

```go
// naturalLogAGMNanobot.go

package naturalLogCalcs

import (
	"math/big"

	ePref "github.com/MikeAustin71/errpref"
)

type naturalLogAGMNanobot struct{}
// agmKernel
//
// Thin wrapper around Macrobot.agmCore that:
//   - builds the initial (a0, b0) pair from a modulus or
//     other normalization data (already decided in your pipeline),
//   - computes a working precision from decimal digits,
//   - and returns AGM(a0, b0) at the requested precision.
func (agmNano *naturalLogAGMNanobot) agmKernel(
	a0, b0 *big.Float,
	calculationDecimalDigits uint,
	errPrefDto *ePref.ErrPrefixDto,
) (*big.Float, error) {

	ePrefix, err := ePref.ErrPrefixDto{}.NewFromErrPrefDto(
		errPrefDto,
		"naturalLogAGMNanobot.agmKernel()",
		"",
	)
	if err != nil {
		return new(big.Float), err
	}

	if calculationDecimalDigits == 0 {
		calculationDecimalDigits = 32
	}

	// Safety margin in digits → bits.
	safetyDigits := uint(4)
	precBits := new(BigFloatHelper).
		ComputeBigFloatPrecisionBits(
			calculationDecimalDigits+safetyDigits,
			1,
		)

	return new(naturalLogAGMMacrobot).agmCore(
		a0,
		b0,
		precBits,
		ePrefix,
	)
}
```

The Molecule/Atom layers you already outlined (e.g. `reduceByPowersOfTwo`, `computeModulusFromXReduced`, `computeLnFromAGM`) will call `agmKernel` with the exact $(a_0,b_0)$ pair dictated by your chosen AGM identity; that part doesn’t change the core iteration.

#### 2. AGM ln(x) vs Taylor ln(x) over a grid

Assuming you already have:

- `naturalLogTaylor.lnTaylorDirect(x *big.Float, precBits uint) (*big.Float, error)`

```go
// xt_naturalLogAGM_vs_Taylor_01_test.go

package naturalLogCalcs

import (
	"math/big"
	"testing"
)

func Test_NaturalLog_AGM_vs_Taylor_DenseGrid_01(t *testing.T) {

	ePrefix := "Test_NaturalLog_AGM_vs_Taylor_DenseGrid_01"

	bFloatHlpr := new(BigFloatHelper)

	// Target ~80 decimal digits for comparison.
	precBits := bFloatHlpr.ComputeBigFloatPrecisionBits(80, 8)

	lnTaylor := new(naturalLogTaylor)
	lnAGM := new(naturalLogAGM)

	// Grid: x in [0.25, 4.0], step 0.05 (for example).
	start := 0.25
	end := 4.0
	step := 0.05

	for xVal := start; xVal <= end+1e-12; xVal += step {

		x := new(big.Float).
			SetMode(big.AwayFromZero).
			SetPrec(precBits).
			SetFloat64(xVal)

		lnT, err := lnTaylor.lnTaylorDirect(x, precBits)
		if err != nil {
			t.Fatalf("%v\nlnTaylorDirect error at x=%v: %v\n",
				ePrefix, xVal, err)
		}

		lnA, err := lnAGM.lnAGMDirect(x, precBits)
		if err != nil {
			t.Fatalf("%v\nlnAGMDirect error at x=%v: %v\n",
				ePrefix, xVal, err)
		}

		// Compare to, say, 60 decimal digits.
		decDigits := 60

		lnTStr := lnT.Text('f', decDigits)
		lnAStr := lnA.Text('f', decDigits)

		if lnTStr != lnAStr {
			t.Errorf("%v\nMismatch ln(x) AGM vs Taylor at x=%v\nTaylor: %v\nAGM:    %v\n",
				ePrefix, xVal, lnTStr, lnAStr)
		}
	}
}
```

This test doesn’t care which exact AGM identity you chose for `lnAGMDirect`; it simply asserts that, once the normalization → modulus → AGM → ln(x) pipeline is wired correctly, the AGM‑based logarithm numerically matches the Taylor implementation to high precision across a broad range.
